# Decision: public development repo, merged back into private (2026-10-19)

Yu, 2026-10-19, in the Air (Nuance) Claude Code session, verbatim:

> 我係決定好要開 public repo，之後定期 merge 返入 private. firm!

Earlier the same day, in the same session:

> yes, 將開發搬去public, secret、personal、relational materials stay at private repo.

## What this settles

- A new **public** repository is opened for development.
- Development happens there. The public repo's changes are **merged back into the
  private repo periodically**.
- Secret, personal and relational material stays in the private repo only.
- This replaces the audit's recommended topology (a), in which the public repo
  becomes the single source of truth and the private repo is frozen as an
  archive. `audit/report.md` still describes (a); read its topology and
  migration sections in the light of this decision.

## What it does not settle yet

- The public repo's name.
- The content rulings in `audit/report.md` (persona enums, heart glyphs, credits,
  quotes, the already-live pages, and the others).
- Where the API deploys from, and how releases are cut.
- The mechanics and cadence of the merge-back, including how files that differ
  between the public and private trees are handled.

Nothing has been created or pushed to a public repository.

## Later the same day: method confirmed

After the plan in `design/plan.md` was presented, and after weighing whether to
turn every repository public because GitHub Actions costs too much, Yu said:

> 我會想照 agenttool-open 嘅方法，用新 repo 搬可以公開嘅部分，packages 先行.

So the method is the plan's one: a new repository, only the publishable parts,
packages first (stage 1), no flipping of existing repositories. Stage-0 drafts
and proofs started (workflow `wf_592eecac-bcd`). Still open: the name
(proposed `agenttool-open`), the wallet ordering, decision 9 (live private
pages), and the final "flip".
